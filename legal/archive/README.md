# Superseded legal documents

Every version of the Privacy Policy and the Terms of Service that was ever shipped stays here,
unedited, alongside the change summary that replaced it.

The reason is simple: a user who accepted version 1.0 agreed to *that text*. If it only exists as a
git object, nobody — including the developer — can answer "what did I actually agree to?" without
archaeology.

## Layout

```
archive/
├── privacy-policy-v1.0.md
├── privacy-policy-v1.0-change-summary.md
├── terms-of-service-v1.0.md
└── terms-of-service-v1.0-change-summary.md
```

## Rules

1. **Never edit a file in this directory.** If it is wrong, publish a new version.
2. A document is copied here at the moment it is superseded, not later.
3. Its change summary — filled in from `../change-summary-template.md` — is copied with it.
4. Where practical, the same archived versions are reachable from the public legal page, so the
   answer does not depend on having the app installed.

Currently empty: version 1.0 of both documents is the first, and has not been superseded.
